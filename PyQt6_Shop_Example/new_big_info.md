# PyQt6 Shop Example

Учебный десктопное приложение «Магазин» на **PyQt6** и **PostgreSQL**. Показывает каталог товаров в виде сетки карточек с поиском, фильтрацией по категории и цене, сортировкой и прокруткой. Проект построен по слоистой архитектуре: UI не знает про SQL, SQL не знает про UI.

## Возможности

- Каталог товаров в виде сетки карточек (число колонок настраивается).
- Поиск по названию без учёта регистра (`ILIKE`).
- Фильтр по категории (выпадающий список из БД).
- Фильтр по диапазону цен (от и до).
- Сортировка: по названию (А-Я, Я-А) и по цене (возрастание, убывание).
- Кнопка «Сбросить» возвращает все фильтры к значениям по умолчанию.
- Прокрутка (`QScrollArea`) при большом числе товаров.
- Заглушка вместо картинки, если файл не найден.
- Сообщение «Ничего не найдено» при пустой выдаче.
- Debounce: запрос в БД уходит один раз через 300 мс после последнего изменения фильтров.
- Два вида карточки: вертикальная (картинка сверху) и горизонтальная (картинка слева).

## Архитектура

Приложение разделено на четыре слоя. Каждый слой знает только о слое прямо под ним.

```
UI Windows  ->  Services  ->  Repositories  ->  DB Units  ->  PostgreSQL
(PyQt6)         (логика)      (SQL-запросы)     (подключение)
```

| Слой | Ответственность | Чего здесь быть не должно |
|---|---|---|
| **UI Windows** | вёрстка на PyQt6, обработка сигналов, отрисовка карточек | SQL, подключение к БД, бизнес-правила |
| **Services** | бизнес-логика, валидация, подготовка параметров | SQL, виджеты |
| **Repositories** | SQL-запросы, преобразование строк БД в словари | бизнес-правила, виджеты |
| **DB Units** | создание подключения к БД, чтение `.env` | запросы, логика, UI |

Сервис и репозиторий имеют одинаковый набор методов по смыслу (`get_products` в сервисе вызывает `get_filtered` в репозитории), но в репозитории метод содержит SQL, а в сервисе только логику и проверки.

> В примере из диалога весь код собран в одном файле для наглядности. Для реального проекта его стоит разнести по папкам, как показано ниже.

## База данных

### Схема

Схема приведена к третьей нормальной форме: категория вынесена в отдельную таблицу и связана с товаром внешним ключом. Название категории не дублируется в каждой строке товара.

```sql
CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    price NUMERIC(10, 2) NOT NULL CHECK (price >= 0),
    image_path VARCHAR(300),
    category_id INTEGER REFERENCES categories(id)
);

CREATE INDEX idx_products_category ON products(category_id);
CREATE INDEX idx_products_price ON products(price);
```

### Тестовые данные

```sql
INSERT INTO categories (name) VALUES
    ('Одежда'),
    ('Обувь'),
    ('Посуда');

INSERT INTO products (name, price, image_path, category_id) VALUES
    ('Футболка хлопковая', 1299.00, 'resources/images.jpg', 1),
    ('Худи оверсайз', 3499.00, 'resources/images.jpg', 1),
    ('Кроссовки беговые', 5990.00, 'resources/images.jpg', 2),
    ('Ботинки зимние', 7490.00, 'resources/images.jpg', 2),
    ('Кружка керамическая', 450.00, 'resources/images.jpg', 3),
    ('Набор тарелок', 2100.00, 'resources/images.jpg', 3);
```

### Типы данных

- `NUMERIC(10, 2)` для цены: точные деньги без ошибок округления, в отличие от `FLOAT`.
- `SERIAL` для первичных ключей: автоинкремент.
- `CHECK (price >= 0)`: защита от отрицательных цен на уровне БД.

## Как это работает

### Поток данных

1. Пользователь меняет фильтр или вводит текст в поиск.
2. Сигнал запускает `QTimer` на 300 мс (если уже запущен, перезапускает его).
3. Таймер срабатывает и вызывает `load_products`.
4. Окно собирает значения всех контролов и передаёт их в `ProductService.get_products`.
5. Сервис проверяет и нормализует параметры и вызывает `ProductRepository.get_filtered`.
6. Репозиторий собирает SQL, выполняет его и возвращает список словарей.
7. Окно очищает сетку и в цикле создаёт карточку на каждую строку.

### Заполнение сетки в цикле

```python
for index, product in enumerate(products):
    row, col = divmod(index, self.COLUMNS)
    card = ProductCard(product["name"], product["price"], product["image_path"])
    self.grid.addWidget(card, row, col)
```

`divmod(index, COLUMNS)` превращает порядковый номер в пару «строка, столбец». Чтобы изменить число колонок, достаточно поменять константу `COLUMNS`.

### Очистка сетки

Перед каждой перерисовкой старые карточки удаляются, иначе они накапливаются:

```python
def clear_grid(self):
    while self.grid.count():
        item = self.grid.takeAt(0)
        widget = item.widget()
        if widget:
            widget.deleteLater()
```

`takeAt(0)` вынимает элемент из layout, `deleteLater()` освобождает виджет.

## Карточка товара: вертикальная и горизонтальная

Любой интерфейс в Qt строится из вложенных layout: корневой layout содержит виджеты и другие layout. Вертикальная и горизонтальная карточки отличаются только выбором корневого layout.

| Вид | Корневой layout | Расположение |
|---|---|---|
| Вертикальная | `QVBoxLayout` | картинка сверху, текст снизу |
| Горизонтальная | `QHBoxLayout` | картинка слева, текст справа |

Блок с текстом в обоих случаях один: маленький `QVBoxLayout` с названием и ценой.

```python
root = QHBoxLayout(self) if horizontal else QVBoxLayout(self)
root.addWidget(image_label)
root.addLayout(info)
```

### Параметры карточки

| Параметр | Описание |
|---|---|
| `name` | название товара |
| `price` | цена |
| `image_path` | путь к картинке |
| `horizontal` | `True` для горизонтальной карточки |
| `image_size` | размер картинки в пикселях |

### Управление размерами

- `image_size` задаёт размер картинки, остальное подстраивается.
- `setFixedWidth` и `setFixedSize` жёстко фиксируют размер карточки.
- `setMinimumSize` и `setMaximumSize` задают допустимые границы.
- `addStretch()` добавляет «пружину», которая прижимает содержимое к краю.
- `setSpacing` и `setContentsMargins` управляют отступами.
- `setWordWrap(True)` переносит длинные названия, и они не распирают карточку.

### Обработка отсутствующей картинки

```python
pixmap = QPixmap(image_path) if image_path else QPixmap()
if pixmap.isNull():
    pixmap = QPixmap(image_size, image_size)
    pixmap.fill(QColor("#dddddd"))
```

Если файла нет или путь пустой, рисуется серый квадрат нужного размера.

## Фильтрация, поиск и сортировка

### Динамический WHERE

Репозиторий собирает условия и параметры в два списка. Каждый включённый фильтр добавляет своё условие и своё значение:

```python
conditions = []
params = []

if search:
    conditions.append("p.name ILIKE %s")
    params.append(f"%{search}%")
if category_id is not None:
    conditions.append("p.category_id = %s")
    params.append(category_id)

where = f"WHERE {' AND '.join(conditions)}" if conditions else ""
```

Так не нужно писать отдельный запрос под каждую комбинацию фильтров.

### Безопасность SQL

- **Значения** всегда передаются через плейсхолдеры `%s` и список параметров. Никаких f-строк со значениями из интерфейса: это защита от SQL-инъекций.
- **Сортировка** не может быть параметром (`ORDER BY` не принимает `%s`), поэтому ключ из UI переводится в готовый кусок SQL через белый список:

```python
SORT_OPTIONS = {
    "name_asc": "p.name ASC",
    "name_desc": "p.name DESC",
    "price_asc": "p.price ASC, p.name ASC",
    "price_desc": "p.price DESC, p.name ASC",
}
order = self.SORT_OPTIONS.get(sort, self.SORT_OPTIONS["name_asc"])
```

Если пришёл неизвестный ключ, используется сортировка по умолчанию. Второе поле в сортировке по цене (`p.name ASC`) делает порядок стабильным при одинаковых ценах.

### Элементы интерфейса

| Контрол | Что хранит | Как читается |
|---|---|---|
| `QLineEdit` | текст поиска | `text()` |
| `QComboBox` категорий | id категории (`None` для «Все») | `currentData()` |
| `QDoubleSpinBox` «от» | минимальная цена (0 = не задана) | `value() or None` |
| `QDoubleSpinBox` «до» | максимальная цена (0 = без лимита) | `value() or None` |
| `QComboBox` сортировки | ключ сортировки | `currentData()` |

`QComboBox.addItem("Текст", значение)` хранит рядом с подписью настоящее значение, и не приходится сопоставлять строки по тексту.

### Валидация в сервисе

```python
if price_min is not None and price_max is not None and price_min > price_max:
    price_min, price_max = price_max, price_min
```

Бизнес-логика живёт в сервисе: ни в окне, ни в SQL.

### Debounce

```python
self.timer = QTimer(self)
self.timer.setSingleShot(True)
self.timer.setInterval(300)
self.timer.timeout.connect(self.load_products)

self.search_input.textChanged.connect(self.timer.start)
```

Каждое изменение перезапускает таймер, а запрос уходит один раз, когда пользователь перестал вводить.

### Сброс фильтров

Перед сбросом контролов сигналы блокируются через `blockSignals(True)`, иначе пять изменений вызвали бы пять перезагрузок. После сброса сигналы возвращаются и `load_products` вызывается один раз.

## Best practices

**Архитектура**

- Один слой, одна ответственность. UI не пишет SQL, репозиторий не знает про виджеты.
- Окно общается только с сервисом, сервис только с репозиторием.
- Бизнес-правила (проверки, нормализация) живут в сервисах.

**Работа с БД**

- Один запрос на весь список. Запрос внутри цикла по карточкам даёт проблему N+1.
- Только параметризованные запросы. Значения никогда не подставляются в SQL через f-строки или конкатенацию.
- Курсоры открываются через `with self.conn.cursor() as cur`, чтобы они закрывались автоматически.
- Для записи (добавление, удаление) нужен `commit()`, а при ошибке `rollback()`.
- Настройки подключения живут в `.env`, а не в коде.
- Деньги хранятся в `NUMERIC`, а не в `FLOAT`.
- Внешние ключи и индексы по полям фильтрации и сортировки.

**PyQt6**

- Импортируй классы явно, без `from PyQt6.QtWidgets import *`: так видно, откуда что взялось.
- Строй интерфейс на layout, а не на абсолютных координатах.
- Удаляй ненужные виджеты через `deleteLater()`.
- Не выполняй тяжёлые запросы в главном потоке на больших данных: используй `QThread` или `QThreadPool`.
- Стили через `setStyleSheet` с привязкой к `objectName`, чтобы они не протекали на дочерние виджеты.

**Качество кода**

- Явно обрабатывай крайние случаи: нет картинки, пустая выдача, перепутанные границы цены.
- Держи классы маленькими: карточка отдельно, окно отдельно.
- Константы (число колонок, задержка debounce, размеры) выноси в атрибуты класса или в конфиг.

## Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `connection refused` | PostgreSQL не запущен или неверный порт | проверь службу и `DB_PORT` |
| `password authentication failed` | неверные данные в `.env` | сверь `DB_USER` и `DB_PASSWORD` |
| `relation "products" does not exist` | таблицы не созданы | выполни `sql/schema.sql` |
| `ModuleNotFoundError: psycopg` | не установлен драйвер | `pip install "psycopg[binary]"` |
| Вместо картинок серые квадраты | неверный путь к файлу | пути относительны к месту запуска, запускай из корня проекта |
| Карточки дублируются при поиске | не очищается сетка | проверь вызов `clear_grid()` перед циклом |
| Окно «подвисает» при поиске | запросы на каждую букву | проверь, что сигналы подключены к таймеру, а не к `load_products` |
| `.env` не читается | файл лежит не в той папке | `.env` должен быть в рабочей директории запуска |

## Что добавить дальше

1. **Пагинация.** `LIMIT` и `OFFSET` в репозитории, кнопки «назад» и «вперёд» в окне, переключение страниц.
2. **Добавление и удаление товаров.** Методы `create_product` и `delete_product` в сервисе и репозитории, форма в отдельном окне, `commit()` и `rollback()` в репозитории.
3. **Корзина.** Таблицы `orders` и `order_items`, кнопка «В корзину» на карточке, очистка корзины после покупки (`clear` на layout).
4. **Редактирование товара.** Диалог с предзаполненными полями, метод `update_product`.
5. **Загрузка данных из Excel.** Скрипт, который читает файл через `pandas` или `openpyxl`, разбивает его на таблицы в 3НФ и загружает в БД.
6. **Фоновая загрузка.** Вынос запросов в `QThread`, чтобы интерфейс не блокировался.
7. **Пул соединений.** `psycopg_pool.ConnectionPool` вместо одного глобального подключения.
8. **Тесты.** Юнит-тесты сервисов с подменой репозитория, интеграционные тесты репозитория на тестовой БД.
